# Shuttle 高斯采样器：精度—安全耦合深度分析

> 日期：2026-10-09　对象：`01_公钥密码_数字签名/shuttle`（SHUTTLE-128/256/512，MLWE FSwA + 免拒绝 IRS）
> 方法：说明书（设计文档 V4，109 页）精读 + 参考实现源码审计 + **独立数值复算**（任意精度 Decimal / Python 大整数逐位仿真）

## 1. 一句话回答"shuttle 的安全为什么和实现绑定"

Shuttle 的 SUF 归约把"理想离散高斯"作为输入（Lyubashevsky FSwA 框架），而签名里所有高斯都由**定点整数硬件**实现：96-bit CDT 表 + Q64 多项式 exp + Q62 分段 log。只要任一环节的实际分布偏离理想分布超过预算，归约就失效，签名输出 z 会带上与私钥相关的偏差——这正是 BLISS 被 Flush-Gauss-Reload / 相对范数 / 单比特时序 / loop-abort 一整套攻击打穿的路径（说明书 §side-channel 逐条引用了 [11][20][21][45][10] 并给出对应防御）。**"理论安全、实现定生死"在这套方案里不是修辞，而是有定理编号的工程约束**（Theorem 1 的 C1/C2 两个条件，各值 1 bit 安全预算）。

## 2. 三条高斯管线与精度入口

| 管线 | 用途 | 实现 | 有限精度环节 |
|---|---|---|---|
| 小 σ 噪声（keygen） | s₁,s₂，σ∈{0.85,0.9,1.0} | 96-bit RCDT 直采（9/10/11 行），尾字节定符号+零折叠 | 表舍入 + 行截断；keygen 每密钥只跑一次，Q_bs 极小，裕量巨大 |
| 宽高斯（签名掩码 y，σ=r=825） | Peikert 卷积 z=256x+y | 基础 σ_s=825/256≈3.2227 的 96-bit RCDT（36 行）+ 均匀字节 y + **ApproxExp Q64 拒绝**（deg-8 多项式 + 7 次平方，域 37×256=9472 输入） | ①表舍入 ②36 行截断折叠 ③exp 相对误差 η ④64-bit Bernoulli 粒度 |
| IRS 免拒绝转移（每个挑战位 ±sk̃·X^j） | 让 z 恰为宽高斯边缘分布 | SamplerU（80-bit 指数+57-bit 尾数 → log₂U）+ ApproxLog Q62（g=2,d=13，绝对误差 <2^-57，实测 2^-59.45）+ Q44 常数 2r²ln2 + 15 对边界的 128-bit 比较（交替级数 N=29 截断） | ⑤log 近似 ⑥常数舍入（2^-65.16）⑦级数截断 ⑧U 的离散化网格 |

**说明书的预算体系**（Theorem 1 + P0→P6 七步混合论证，全部用 Rényi 散度）：

- 查询预算：NGCC 上限 **2^80 签名/密钥**，Q_bs = Q_exp = 2^80·n(ℓ+m+1)/0.8 ≈ **2^91.1~92.9**；
- **C2（基础采样器）**：R_{2λ+1}(RCDT ‖ D_{Z+,σs}) ≤ 1+1/(4Q_bs)。绑定最紧的是 SUF-512：阈值 **1+2^-94.91**，出厂表实测 **1+2^-95.40**（⚠️ 仅 0.49 bit 裕量）；R_257 = 1+2^-95.55。
- **C1（拒绝概率）**：接受支相对误差需 2η/(1−η) ≤ 2^-50.06/50.95/51.95（三个等级）；ApproxExp 实测 **η=2^-54.49** → 2^-53.49（1.5 bit 裕量）。
- IRS 链：内蕴误差 M3 < 1+2^-82；级数截断 M4 < 1+2^-92；log 精度 M5 与 M3 共享 1+2^-82 预算（δ_log 经 τ=115 步累计 < 2^-45，在 2^-45 预算内）。
- 总计：用真实采样器替换理想高斯，**底层搜索问题至多损失 2 bit**。

| R₂₅₇（λ=128） | — | 1+2^-95.55 | ✅ C2 通过 |

| 平均接受率 p_acc | ≈0.89 | **0.8903** | ✅ |
| 表 = 精确尾概率最近舍入 | 隐含（"可由说明书独立复现"） | **否：36 行全部偏小 8~19 ulp₉₆（≈2^-91.6 绝对偏置，方向一致）**；与 Python `decimal` 默认 prec=28（≈93 bit）生成结果差 ≤3 ulp，高度疑似生成器算术精度所致 | ⚠️ F2 |
| 括注 "R_∞ = 1+2^-89.55" | 1+2^-89.55 | **无法复现**：按逐格比值，折叠格 x=36 的质量比 ≈0.94（vs 无穷理想格）→ R_∞≈1.06 | ⚠️ F3（无实质影响，见下） |

**最少需要多少 bit（θ×L 联合优化，重新生成表，按 C2 阈值判定）：**

| 场景 | Rényi 阶 | Q_bs | C2 阈值 | 最小 θ（配 L） | 出厂 96-bit 冗余 |
|---|---|---|---|---|---|
| SUF-512，NGCC 2^80 签名 | 1025 | 2^92.91 | 2^-94.91 | **θ=80, L=28**（达 2^-98.65） | ~16 bit |
| SUF-128，NGCC 2^80 签名 | 257 | 2^91.13 | 2^-93.13 | **θ=73, L=28**（达 2^-93.62） | ~23 bit |
| SUF-512，标准 2^64 签名 | 1025 | 2^76.91 | 2^-78.91 | **θ=70, L=28**（达 2^-80.15） | ~26 bit |
| SUF-128，标准 2^64 签名 | 257 | 2^75.13 | 2^-77.13 | **θ=70, L=28**（达 2^-82.15） | ~26 bit |

两个要点：
- **约束主要是查询预算 Q_bs（≈log₂Q+2），不是 λ 本身**（阶 2λ+1 只贡献个位数 bit）。"64 或 78 位"两个历史数字恰好落在这条标尺上：BLISS 时代 64-bit CDT 表对应更宽松的预算/论证；Shuttle 的直接理论来源（Howe–Prest–Ricosset–Rossi, PQCrypto 2020《Isochronous Gaussian Sampling》）在 Falcon 实例化中用 **72-bit CDT**、其 C2 阈值即 **2^-78**。
- **降 θ 不是把 96-bit 表截短那么简单**：固定 L=36 直接把表舍到 64~92 位会出现相邻阈值舍入相撞→质量清零，R₁₀₂₅ 暴增到 2^-1~2^-5 量级（复算验证）。必须 θ 与截断长度 L 联动（小 θ 配小 L，把折叠尾巴留在质量 ≳2^-θ 的格上）。

## 4. "理论安全 vs 实现"的量化注脚：float64 恰好压线

若把 ApproxExp 换成 binary64 `exp()`（典型 1 ulp ≈ 2^-53）：
- 2η/(1−η) = **2^-52.00**，而 SUF-512 阈值 **2^-51.95** → 裕量 **0.05 bit**，实际 libm 1~2 ulp 误差下 C1 在 λ≥256 直接不成立；
- Shuttle 的整数多项式（Q64 + Horner + 7 次平方，全程无分支无除法无浮点）把 η 压到 2^-54.49，才买到 1.5 bit 裕量。
这正是"同样的数学、不同的实现精度，安全性差一档"的实例：**任何向 float/低精度定点移植（32-bit MCU、无 __int128 平台）都必须重做 C1/C2 论证**。

## 5. 审计发现（F1–F5，均不构成可利用漏洞）

- **F1（裕量偏薄，info）**：C2 在 SUF-512 只有 0.49 bit 裕量。参数任何漂移（每签名采样数增多、签名预算上调、表重生成时舍入差几个 ulp）都可能跌破。出厂表最后一行 Z[35]=13 ulp₉₆，而理想尾概率对应 ≈13.8 —— 若生成器把它舍到 ≥17，折叠格质量比将越过 1，按 C2 字面（对无穷理想）R₁₀₂₅ 会暴增。当前表安全，但**这个 0.49 bit 是"表逐 ulp 相关"的**。
- **F2（复现性缺陷，info）**：出厂表 ≠ 精确尾概率的最近舍入（系统性 −8~−19 ulp₉₆）。说明书声称"表可由说明书独立复现"不成立——复现还依赖其生成工具的算术精度（疑似 Python decimal 默认 28 位十进制 ≈93 bit）。散度分析是对出厂表做的（我也复算一致），故安全性不受影响，但审计/交叉验证时会踩坑。
- **F3（文档错误，info）**：括注"R_∞=1+2^-89.55"复现不出（逐格 R_∞≈1.06，源于折叠格 −6% 质量偏差）。对定理无影响（只需 R_{2λ+1}；a>1 阶 Rényi 对**向下**偏差格天然宽容），但表述误导。附带事实：SUF-128 的范数门 B_v=7356 < 9216，折叠区 |z|≥9216 的系数根本无法通过验证；SUF-256/512（B_v=10385/25194）可少量通过，但受影响区质量 ~2^-92，2^80 签名预期命中 <1 次，统计上不可检测。
- **F4（等时性设计亮点，正面记录）**：免拒绝 IRS 消灭了 BLISS 式重试计数泄漏（内层固定 18τ 字节、无秘密依赖分支）；符号位流按输出位置索引（与接受事件解耦），z==0 折叠复用同一符号位、质量守恒；CT-1 用 volatile 累加器阻止编译器把扫描自动向量化成 gather。这些是对 [11][20][21][45] 的逐条针对性防御。
- **F5（本次未覆盖，后续清单）**：①ApproxLog 的 2^-59.45 只对连续域抽样可信，未逐点验证；②SamplerU 的 U 离散化（2^137 网格）对转移概率的阶梯效应未独立分析；③Additional_Implementation（AVX512 版）与 ref 的逐位等价性（byte-exact KAT 门）未复核；④三个噪声小表（σ=0.85/0.9/1.0）及"零折叠后标准差钉在 2^-16 相对误差"未复算；⑤gen_rcdt.py 本体不在提交包中（只有生成结果），F2 的成因推断无法最终定谳。

## 6. "多少 bit 才精确 / 小整数如何高效"——给论文叙事的三句话

1. **需求侧公式**：定点 CDT 表精度 θ ≳ log₂Q_bs + 2 +（阶修正 ~log₂(2λ)/2），由签名预算主导；NGCC 2^80 预算下 θ_min≈73~80，标准 2^64 预算下 θ_min≈70，历史数字 64（BLISS）/72/78（等时采样论文）与 96（Shuttle，3×32 SIMD 友好 + 三级共享 + 全等级裕量）都落在这条标尺上，Shuttle 的 96 是"带 16~26 bit 冗余的工程舒适位"而非临界值。
2. **效率侧答案**：Shuttle 把精度全部挪进**静态表**（宽表 432 B，36 行×12 B）和 **64-bit 整数 lane**（Q64 exp、Q62 log、__int128 高半乘），运行时数据全是小整数——基础样本 0~36（6 bit）、秘密 |s|≤15（5 bit）、签名系数 |z|≤B_v（13~15 bit）。即"高效=小整数"的正确打开方式：不是砍精度，而是让精度只存在于常数里。
3. **移植警告**：换 float64、砍表位数、或改截断长度而不重推 C1/C2，都会以 0.05~几个 bit 的裕量悬崖形式破坏归约（§4、§3 的扫描数据即证据）。
